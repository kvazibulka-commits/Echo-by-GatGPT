# ЭХО / Echo Radar — конституция проекта

## Продукт
ЭХО — гео-музыкальный радар присутствия. Это НЕ соцсеть, НЕ дейтинг, НЕ плеер.
«Ты видишь не людей вокруг. Ты видишь музыку, которая сейчас живет вокруг тебя».
Везде первичны Artist — Track и жанр; человек вторичен.

Запрещены фотографии людей, лайки, сердечки, подписчики, рейтинги, стрики,
чаты и технические аудио-метрики (темп, тональность, размер такта).
Никаких декоративных деревьев, полумесяцев и случайных эмодзи.
Вместо аватаров — генеративные абстрактные формы.

Стиль: кинематографичный темный минимализм, монохром и глубокий обсидиан,
выразительная типографика, ночной сонар, детерминированно вращающийся винил.
Музыка воспроизводится внешним системным плеером; ЭХО захватывает метаданные.

## Навигация и UX
Нижняя навигация в зоне большого пальца, ровно четыре экрана:
1. Эфир — круговой радар, один сигнал = один звучащий трек рядом.
2. Дека — винил текущего трека, системные метаданные, ручной ввод,
   тумблер «Открыт для музыкальных встреч».
3. Капсулы — гео-музыкальные тайники в точках города.
4. Хроника — анонимный вечерний дневник пересечений («Вы уже 3-й раз оказались
   рядом»), литературный архетип и сохраненные треки.
Карточки сигналов — исключительно ModalBottomSheet, без AlertDialog.
Отклик — только тихий атмосферный импульс, без сообщений и социальных счетчиков.

## Архитектура
- Бесплатная работа в РФ, без платных API, аккаунтов и внешнего AI.
- Python 3.12+, стандартная библиотека: server/echo_server.py, HTTP + UDP.
- SQLite WAL, отдельное соединение на операцию, busy_timeout; составные изменения
  и encounters_count — в BEGIN IMMEDIATE с атомарным UPSERT и дедупликацией.
- HTTP API /api/signal, /api/state, /api/sync, /api/capsules, /api/impulses,
  /api/encounters; JSON snake_case. Контракт описан в README.md.
- Сигналы истекают через 90 секунд без heartbeat. Пересечения пары считаются
  повторно после 30 минут. Координаты сигналов огрубляются до 0.01 градуса;
  координаты публичной капсулы — явно выбранная точка, не геопозиция человека.
- Android: Kotlin, Compose, Material3; ru.echo.radar, minSdk 26, targetSdk 34,
  JDK 17. UI, модели, движок, repository, media и discovery — отдельные файлы.
- EchoMediaListenerService: NotificationListenerService + MediaSessionManager,
  callbacks и резервный опрос; никаких разрешений чтения всех уведомлений в UI.
- SerendipityEngine — локальное детерминированное сравнение жанров/артистов и
  литературные архетипы. Не выдумывать жанр по названию трека.
- BLE manufacturer ID 0x0ECA: версия + 8 байт хэша сессии + 8 байт хэша трека.
  Это прототипный ID, не утверждение о регистрации Bluetooth SIG.
- UDP — обнаружение HTTP-узла в LAN, не обход авторизации.
- StateFlow в EchoStateRepository — источник состояния текущего трека.
- PWA в server/web: без CDN, сервис-воркер не кэширует API и секреты.

## Безопасность и качество
Все SQL-параметры привязаны, вход валидируется, размеры запросов ограничены.
ECHO_TOKEN — только окружение; при его наличии требуется для всех API кроме health.
Без токена доступ разрешен только прямому LAN/loopback, proxy-заголовки требуют
токен. Для интернета нужен собственный HTTPS reverse proxy и ECHO_TOKEN.
Не логировать секреты. Не коммитить БД, local.properties, APK, ключи и кэши.
Проверять Python py_compile, тесты API/транзакций и Gradle assembleDebug/testDebugUnitTest.
Отличать проверенный APK от статически проверенной структуры проекта.

## Правило точечных правок
Перед правкой читать файл и связанные вызовы. Сохранять рабочий код и существующие
импорты; удалять импорт только если он действительно больше не используется.
Не заменять работающий модуль сокращенной демонстрацией. Не делать гигантский UI
в одном файле. Никаких TODO-заглушек, фиктивных сигналов и проглоченных исключений.
Изменение контракта сопровождается документацией и проверкой его потребителей.
Пользовательская конституция выше устаревших примеров из навыков.
