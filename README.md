# ЭХО / Echo Radar

Гео-музыкальный радар присутствия: ты видишь музыку, которая сейчас живет вокруг.
Конституция, ограничения интерфейса и правила разработки — в [AGENTS.md](AGENTS.md).

## Этап 1 — фундамент

Сервер уже обслуживает HTTP JSON API, SQLite WAL, UDP-обнаружение и легкую PWA.
Android содержит модели, локальный SerendipityEngine, перехват медиа-сессий,
BLE advertiser/scanner, UDP discovery и рабочую деку для проверки захвата и
ручного ввода. Никаких искусственных сигналов или внешних музыкальных API.

Четыре полноценных экрана, сонар, виниловая анимация, ModalBottomSheet,
сохранение хроники на Android и подключение Android repository к HTTP — следующий
этап. BLE/UDP предоставлены отдельными lifecycle-компонентами: экран пока их
не запускает и не запрашивает разрешения поиска. Фоновое BLE не заявляется.

## Запуск сервера

Python 3.12 или новее, установка зависимостей не требуется:

```powershell
python server/echo_server.py
# http://localhost:8080/app
python -m py_compile server/echo_server.py
python -m unittest discover -s tests -v
```

Настройки: `--host`, `--port` (8080), `--udp-port` (45454), `--db`.
Окружение: `ECHO_DB_PATH`, `ECHO_TOKEN`. БД создается автоматически, версия схемы 1.
Для телефона откройте TCP 8080 и UDP 45454 в локальном брандмауэре.

Без токена узел доверяет прямым клиентам LAN. Это режим доверенной локальной сети,
а не индивидуальная авторизация устройств: участник узла способен объявить чужой
session_id. Не используйте его как публичный многопользовательский сервис.
При `ECHO_TOKEN` каждый API-запрос, кроме health, требует `X-Echo-Token`.
Proxy-заголовки никогда не дают LAN-обход. Для внешнего доступа нужны токен и HTTPS;
индивидуальные ключи устройств и защита от подмены сессий — до публичного релиза.
Токены не передаются через URL, не сохраняются в PWA и не входят в APK.

## API v1

Имена полей — snake_case. Время — Unix seconds UTC. Все POST — JSON до 16 КиБ.
Ошибки — `{"error":"..."}` с HTTP 400/401/403/404/409/413/415/429/500.
Координаты должны передаваться парой конечных чисел. session_id и ID события —
ASCII буквы, цифры, `_` или `-`, до 64 символов; выбирайте случайный UUID.

| Метод | Путь | Вход | Результат |
|---|---|---|---|
| GET | `/api/health` | — | status, version |
| POST | `/api/signal` | session_id, artist, title, genre?, source?, open_to_meet?, latitude?, longitude? | session_id, expires_at |
| GET | `/api/state?session_id=...` | session_id | signals, encounters, impulses, server_time |
| POST | `/api/sync` | session_id | то же состояние, атомарно обновляет пересечения |
| GET | `/api/capsules?latitude=...&longitude=...` | координаты центра | capsules в радиусе 5 км |
| POST | `/api/capsules` | creator_id, artist, title, genre?, note?, latitude, longitude | id (201) |
| GET | `/api/encounters?session_id=...` | session_id | encounters |
| GET | `/api/impulses?session_id=...` | session_id | impulses за последние сутки |
| POST | `/api/impulses` | id, sender_id, target_id | id (201), повтор того же события безопасен |

Сигнал живет 90 секунд: heartbeat повторяет POST /api/signal. Браузер на скрытой
вкладке прекращает heartbeat. Импульс отправляется между двумя активными сигналами,
не чаще одного раза в 5 секунд от сессии. Текстовых сообщений нет.

Сигналы сохраняются с координатами, округленными до 0.01 градуса; это
приблизительная зона присутствия, не точная дистанция. Без координат сигналы не
попадают в выдачу «рядом». Радиус выдачи 1500 м по огрубленным координатам.
Капсулы используют явно выбранные публичные координаты и не истекают.

Пересечение — одна упорядоченная пара сессий в encounters. BEGIN IMMEDIATE и
UPSERT сериализуют конкурирующие запросы; encounters_count растет при возвращении
после отсутствия наблюдений пары минимум 30 минут. Постоянный polling не создает
новых встреч. Поскольку мобильные сессии анонимны, очистка данных браузера
обрывает преемственность хроники. Долгосрочное хранение и удаление истории
потребуют отдельной продуктовой настройки.

## Локальное обнаружение

UDP IPv4 broadcast `ECHO_DISCOVER_V1` → узел отвечает `ECHO_V1:8080`.
HTTP origin строится из IP отправителя ответа, не из недоверенного URL в payload.
UDP не передает треки, геопозицию или команды записи. Изоляция Wi-Fi клиентов
может блокировать обнаружение; тогда адрес узла вводится вручную на следующем этапе.

BLE manufacturer-specific data ID **0x0ECA**, payload **17 байт**:
версия `0x01`, первые 8 байт SHA-256 UTF-8 session ID, первые 8 байт SHA-256
идентификатора трека. Порядок — как в digest, без преобразования в integer.
Рекомендуемый идентификатор трека — нормализованные `artist|title`.
Это короткие сопоставимые маяки, а не шифрование: трек можно угадать по словарю.
Меняйте session ID при начале нового вечера. ID прототипный; для коммерческого
BLE-продукта нужно проверить назначение Company Identifier в Bluetooth SIG.

## Android

JDK 17, Gradle wrapper 8.7 (с SHA-256 дистрибутива), AGP 8.5.2, Kotlin 1.9.24,
Compose compiler 1.5.14, Compose BOM 2024.06.00, minSdk 26, compile/targetSdk 34.
Версии закреплены для воспроизводимости заданного SDK, это не заявление об их новизне.
Совместимость: [AGP 8.5](https://developer.android.com/build/releases/agp-8-5-0-release-notes),
[Compose / Kotlin](https://developer.android.com/jetpack/androidx/releases/compose-kotlin).

```powershell
.\gradlew.bat :app:assembleDebug :app:testDebugUnitTest :app:lintDebug
```

На телефоне нажмите «Подключить системный плеер» и включите доступ ЭХО к
уведомлениям. BIND_NOTIFICATION_LISTENER_SERVICE — permission на service,
а не запрашиваемое приложением runtime-разрешение. Служба использует allowlist
Яндекс Музыки, VK, Звука, Spotify и YouTube Music; доступность метаданных зависит
от конкретного плеера. Callback сессии + опрос 2.5 с, уведомления — fallback.
Ручной трек имеет приоритет до действия «Вернуться к системному плееру».
Реальные плееры и BLE требуют отдельного прогона на устройстве.

BLE на Android 12+ требует SCAN, ADVERTISE, CONNECT; на Android 8–11 — геолокацию.
Никакие RSSI и аудио-метрики не предназначены для UI. Жанр берется только из
реальных метаданных или ручного ввода; отсутствие жанра не означает совпадение.
Резонанс: 40 баллов за совпадение нормализованного артиста + 60 × Jaccard жанров;
это локальная объяснимая эвристика, не социальный рейтинг.

## PWA / iOS

`/app`: просмотр музыки рядом, ручная трансляция, импульсы, список капсул.
Service Worker кэширует только оболочку. На iOS нет системного перехвата музыки,
Web Bluetooth advertiser недоступен: музыка задается вручную, обнаружение через
HTTP-узел. Установка PWA и геолокация требуют HTTPS (или localhost при разработке).
При обычном HTTP в LAN можно просмотреть страницу, но браузер не даст район.
Четыре полноценных продуктовых экрана PWA также относятся к следующему этапу.

## GitHub Actions

`.github/workflows/build-apk.yml` запускается на push, pull_request и вручную:
Python 3.12 tests → JDK 17 → лицензии/SDK 34 → Gradle cache → assembleDebug,
unit tests и lint. APK — в артефакте **echo-debug-apk**, файл `app-debug.apk`.
Debug-подпись предназначена для разработки, не для выпуска в магазин.
GitHub-hosted runner не запускает постоянный сервер ЭХО.
Стоимость Actions зависит от тарифа/квоты GitHub; сам продукт не требует платных API.

Доступ к репозиторию можно дать через интеграцию GitHub или fine-grained token:
только нужный репозиторий, Contents RW, Workflows RW, Actions Read.
Токен хранить в окружении GITHUB_TOKEN или локальном игнорируемом `.github-token`.
Никогда не добавлять его в remote URL, командную строку или коммит.
