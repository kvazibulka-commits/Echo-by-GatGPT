# Доставка итоговой сборки

Место назначения согласовано: Google Drive / ЭХО / echo-latest.apk.
Это действие агента после каждой выполненной им итоговой сборки. Отдельный
непрерывный CI → Drive pipeline пока не создан.

1. Дождаться успешных assembleDebug, Kotlin tests и lint в Actions для нужного
   commit. Не заменять рабочий APK результатом непрошедшей проверки сборки.
2. Скачать echo-debug-apk нужного запуска. Если API-токен недоступен, использовать
   действующий вход в GitHub через браузер. Не создавать новые токены без нужды.
3. Сравнить SHA-256 ZIP с digest артефакта из Actions; при расхождении остановить
   доставку. Извлечь только ожидаемый app-debug.apk, проверить APK как ZIP с
   AndroidManifest.xml и classes.dex, вычислить SHA-256 и размер APK.
4. Прочитать локальный .echo-delivery.json. Он не содержит токенов, но приватные
   ссылки и ID не предназначены для публичного repo. Если его нет, найти точную
   папку «ЭХО» и echo-latest.apk в Drive; не создавать дубликат существующего файла.
5. Получить метаданные file_id и подтвердить имя/папку. Обновить байты через
   google_drive.update_file(fileId=..., file_uri=абсолютный_путь,
   mime_type=application/vnd.android.package-archive). upload_file используется
   только для первой загрузки, когда существующий файл не найден.
6. Прочитать метаданные после записи: прежний ID, имя, MIME, ожидаемый размер и
   родительская папка. Не заявлять сравнение удаленного SHA-256, если connector
   его не вернул. При необходимости скачать файл обратно и сравнить хэш.
7. Только после проверки обновить локальный JSON (run_id, commit, sha256,
   size_bytes, file_id, folder_id, file_url) и летопись. Вернуть пользователю
   ту же Drive-ссылку и назвать оставшиеся ограничения/следующий шаг.

Не менять настройки доступа: загрузка в личный Drive не означает разрешение
сделать APK публичным. Не помещать Google/GitHub credentials в APK или репозиторий.
